## 🔥 Свежее: 2026-08-09 — Кнопка возврата в видео-портале kinogo (маска)

**Статус:** сделано локально, сборка `npm run build` проходит. НЕ задеплоено.

**Симптом:** внутри видео-портала kinogo (iframe) курсор/навигация работает с сайтом,
но НЕ было видно нашего курсора и НЕ было пути назад в StreamLume — пользователь
«застревал» в портале. Особенно на ТВ, где нет системного курсора над iframe.

**Корень проблемы (важно для понимания):**
- «Наш курсор» на главной — это ФОКУС-навигация (стрелки двигают `tv-focus` по нашим
  DOM-элементам). Она живёт ТОЛЬКО в нашем собственном документе.
- kinogo открыт как **cross-origin `<iframe>`** → наш JS не может ни двигать фокус по
  элементам внутри него, ни кликать `elementFromPoint` внутрь фрейма (same-origin policy).
- Раньше код делал `iframe.focus()` — это УВОДИЛО клавиатурный фокус в iframe, из-за чего
  кнопка «Назад» на пульте переставала доходить до нашего обработчика.

**Решение (`src/screens/PortalScreen.tsx`, полностью переписан):**
1. Намеренно **НЕ вызываем `iframe.focus()`** → клавиатурный фокус остаётся в родителе.
   → кнопка «Назад» пульта ловится `index.html` (portalMode) и вызывает `closePortal`.
2. Мышь при этом свободно кликает по kinogo — мышь НЕ требует клавиатурного фокуса,
   клики уходят в iframe по позиции указателя.
3. Поверх iframe наложена **«маска» с кнопкой «Назад в StreamLume»**, которая сама
   **прячется через 5 сек** (чтобы не перекрывать сайт).
4. Сверху — тонкая невидимая полоса-ловушка (`revealStrip`, 16px): навёл курсор наверх
   → кнопка снова появилась. Любая клавиша тоже показывает кнопку (`revealMask`).

**Логика исчезновения:** `maskVisible` (true при входе) + `hideTimer` 5000 мс.
Появление: `onPointerEnter/Move` по `revealStrip`/`maskBar`, либо `keydown`.

**Проверено:** `npm run build` — OK, бандл собран без ошибок.
**⚠️ За пользователем:** проверить на ТВ —
  (а) кнопка «Назад» пульта выходит из портала;
  (б) мышь кликает по kinogo, пока маска скрыта;
  (в) наведение курсора на верхний край → кнопка появляется снова.

**НЕ трогал:** `PortalPlayerScreen.tsx` (виртуальный курсор для плеера) — там другая
схема. Если плеер тоже нужно переключить на маску — отдельная задача.

## 🔥 2026-08-08 — Починка каталога kinogo на ТВ (задеплоено)

**Коммит:** `a13f6ad` (запушен в main, Netlify деплоит).

**Симптом:** видео-портал kinogo грузил каталог на ПК/Android, но НЕ на Smart-TV
(«Не удалось загрузить фильмы»), даже после холодного старта (дело НЕ в кеше).

**Найдено две причины (живыми тестами 08.2026):**
1. **Весь пул CORS-прокси держался на одном `proxy.cors.sh`.** Остальные 5
   (allorigins, codetabs, corsproxy.io, netlify-proxy) получают 403/521 от
   Cloudflare — CF блокирует дата-центровые IP. Единственная точка отказа:
   если сеть ТВ режет proxy.cors.sh → весь каталог падает.
2. **`Promise.any` (ES2021) отсутствует на старом WebKit ТВ** → парсер падал с
   `TypeError` ещё до запросов. Та же семья багов, что `Array.prototype.at`
   (белый экран, HANDOFF ниже).

**Что починено в `src/utils/kinogoParser.ts`:**
- Добавлен **`cors.io`** (живой, обходит CF, проверен) — теперь **2 рабочих
  прокси** вместо 1.
- `PROXIES` → массив объектов `{name, build, unwrap}`; распаковка завязана на
  структуру ответа, а не на хрупкий поиск строки URL в `unwrap()`.
- **`Promise.any` → `Promise.allSettled` (ES2020)** + ручной выбор первого
  fulfilled — совместимо со старым WebKit.
- Ошибка показывает **имена упавших прокси и причины** (было безликое «Все
  CORS-прокси недоступны»).

**Проверено:** smoke-тест — парсер извлекает 10 фильмов из `kinogo_test.html`,
cors.io JSON-обёртка корректно разворачивается, babel-синтаксис OK, build OK.

**⚠️ За пользователем:** проверить на ТВ, что каталог теперь грузится. Если
всё ещё падает — значит сеть ТВ режет ОБА прокси (proxy.cors.sh + cors.io);
тогда нужен FlareSolverr на VPS как надёжный обход CF (серверный прокси).

**⚠️ Качество контента:** kinogo крутит кам-рипы (снято в зале на смартфон).
Пользователь недоволен качеством. Рассматривали альтернативы:
- Internet Archive (легально, стабильно, public domain классика — НЕ новинки).
- IDC portal.idc.md — отличный контент (Ultra HD, новинки 2026), но требует
  вход абонента IDC и НЕ отдаёт embeddable URL потока (закрытый портал
  провайдера, как Lampa). Подробное исследование IDC — см. лог чата сессии.
- temptcdn-балансёр (токен kinogo webSite=752) — встроил, потом откатил:
  чужой партнёрский токен в коде = правовой риск, особенно при коммерческом
  использовании. Весь TMDb+temptcdn код удалён, парсер чисто kinogo-only.

### Конспект был неточен про «конфликт двух роутеров»
Из `msx/menu.json` выяснено: **MSX и React НЕ работают одновременно**.
MSX — это отдельный лаунчер на TV, который по кнопке «ЗАПУСТИТЬ STREAMLUME»
**редиректит** на `streamlume-tv.netlify.app`. Дальше работает чистый React.
Так что конфликт роутеров — НЕ корень проблемы.

### Истинный корень (доказано анализом бандла `dist/`)
В собранном `dist/_expo/static/js/web/index-*.js`:
- `Array.prototype.at` — **0 определений** ❌
- `String.prototype.at` — **0 определений** ❌
- `Array.prototype.flat`, `flatMap`, `Promise.allSettled`, `findIndex`,
  `Object.assign`, `Array.from`, `includes` — **все 0** ❌

Хотя в `index.ts` написано `import 'core-js/stable'`,
**ни один полифилл не попал в бандл**. Metro/Expo tree-shaking выкинул всё,
либо babel-preset-expo + browserslist `chrome >= 38` не добавил их.
Это и порождает `ReferenceError: at is not defined` на старом WebKit TV.

### Предварительное решение на будущее (НЕ применялось)
Принудительно вставить полифиллы прямо в `public/index.html` как
`<script>`-тег ПЕРЕД загрузкой React-бандла. Не зависит от Metro.
